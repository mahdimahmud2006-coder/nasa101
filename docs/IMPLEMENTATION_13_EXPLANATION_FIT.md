# Implementation 13 — Change DNA, Explanation Fit and claim ledger

Phase 4, 2 November 2026 (Asia/Dhaka).

1. **Changed:** all four cases now have `evidence-v2/` fixed-footprint DNA and Parquet. The original Nepal footprint remains the 199-pixel reference. Each Bangladesh case retains its original common-valid study window and adds three largest retrospective first/last dark-transition components. Selection bias is explicit and does not establish water, habitat or event truth. Runtime map neighborhoods and user-drawn polygons use the same native-pixel arithmetic; no result is written back into frozen products.

2. **Rules:** `rules/explanations.yaml` is a versioned YAML 1.2 JSON subset, intentionally parsed with the standard-library JSON parser. No undeclared PyYAML dependency was introduced. The deterministic engine retains supporting, contradicting, unmet and missing signatures for six hypotheses. Statuses are consistent / not contradicted / contradicted / unknown under uncalibrated rules, not physical probability or ground truth. Multiple fits are allowed and there is no winner. Each visit records next missing nominal acquisition and independent evidence needed. A flat footprint contradicts only the specifically steep-source hypothesis, not all possible mass-movement runout.

3. **DNA:** mean signed ΔHH/ΔHV/ΔCPR, mean absolute pixelwise HH change, threshold onset bracket, observed-visit k/n persistence, sampled recovery fraction and a censored half-crossing interval. Eligibility requires the same native pixels across all dates and channels. Unknown measurements stay null. Coherence remains null/planned; no historical case matching is fabricated. Terrain is summarized on the actual footprint with repeated native-cell weighting; rain is separately unavailable, never replaced.

4. **Claims:** `claims/claims.yaml` drives generated README text, the in-app Claims panel and `docs/VIDEO_CLAIMS_claims-phase4-v1.md`. Numeric result literals in README/app source are checked against ledger values; dynamic footprint metrics are covered by TP-DNA with source/rule provenance. Technical identifiers, code and playback settings are not treated as measured results. The check cannot prove every arbitrary sentence semantically; numerical source validators remain separate. The historical README is retained as an explicitly dated snapshot, not current verification.

5. **Verification:** phase entry was 225 Python / 51 JavaScript tests and eight validators. New tests cover every rule status, null arithmetic, onset/persistence/recovery censoring, malformed/outside/self-crossing polygons, socket-free API requests, claim drift and unknown numeric results, selected footprints and UI rule/claim rendering. Final counts are recorded in the phase summary. Browser visual/accessibility/GPU checks remain unverified; controller tests are mocks.

6. **Use:** restart `./run.sh`, open investigations, choose a saved footprint or click a map neighborhood. Use Draw footprint, select at least three vertices and Inspect polygon. The Competing explanations panel and exported dossier include DNA/rules/missing evidence. `make validate-dna-v2` and `make claims-check` verify source consistency. No runtime LLM, external API call or new raw radar download. Next authorized work remains reference design/evaluation and the interferometry gate.
